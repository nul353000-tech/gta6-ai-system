GTA 6 AI SYSTEM — API
====================

CONTENU DU DEPOT
- app.py : API FastAPI avec authentification Bearer, analyse de texte et d'images.
- Dockerfile, requirements.txt et render.yaml : configuration de l'API et du déploiement.
- tests/ : tests automatisés sans appel réseau au fournisseur IA.

Les sources de l'application Android et de l'interface web annoncées dans d'anciennes
instructions ne sont pas présentes dans ce dépôt. Il n'y a pas non plus de workflow GitHub
Actions pour compiler un APK. L'API peut être appelée depuis ces clients lorsqu'ils seront
ajoutés ; aucun client n'est fourni ici.

CONFIGURATION
Définir ces variables dans l'environnement du service :
- OPENAI_API_KEY : clé API OpenAI, conservée uniquement côté serveur.
- APP_ACCESS_TOKEN : jeton Bearer long et aléatoire, à configurer dans le client.
- OPENAI_MODEL : modèle compatible avec Responses API ; valeur par défaut gpt-6.1-terra.

Ne commitez jamais de clés ou jetons. Le endpoint /health vérifie que le processus répond ;
il ne vérifie pas l'accès aux identifiants OpenAI. Sans APP_ACCESS_TOKEN ou OPENAI_API_KEY,
/v1/assistant renvoie une erreur de configuration.

API
- GET /health : contrôle de disponibilité.
- POST /v1/assistant : en-tête Authorization: Bearer <APP_ACCESS_TOKEN> et JSON
  {"prompt":"...", "image_data_url":"data:image/png;base64,..."} (image facultative).
- Les images JPEG, PNG, WebP et GIF sont limitées à 5 Mo ; les octets sont vérifiés
  par signature avant leur envoi au fournisseur.
- Les appels utilisent l'API OpenAI Responses avec store=false. La mémoire conversationnelle
  n'est pas conservée côté serveur.

DEPLOIEMENT RENDER
Le Blueprint utilise le Dockerfile et le contexte à la racine du dépôt. Connecter
render.yaml au service Render, configurer les deux secrets ci-dessus et déployer depuis
la branche choisie. Aucun déploiement réel ni appel OpenAI réel n'a été effectué pendant
les vérifications locales.

TESTS
Installer les dépendances de développement avec `pip install -r requirements-dev.txt`,
puis lancer `pytest`. Les tests simulent le fournisseur OpenAI et ne nécessitent pas de clé.
